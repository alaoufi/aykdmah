# AYK-174 — تدرجات الأدوار وكثافة الرئيسية والنشر

تصميم طلبه واعتمده المالك: مقدم الخدمة بتدرج أزرق خفيف من الشعار، والطالب/الطلب ببرتقالي خفيف، والخلفية تتبع القالب. تصغير بطاقات أحدث الطلبات ووضع معلومات متجاورة وفلتر منسدل، وإصلاح زر الاستعراض المتداخل، ثم نشر وإرسال APK.

1. تحديث tone-provider/tone-request المركزيتين باستخدام ألوان الشعار وسطح القالب؛ تدرج body يشمل القالب الافتراضي مع استثناء التباين العالي. إضافة النبرة للبطاقات العامة التي تعرض خدمات مقدمة.
2. إزالة الهامش السالب من Categories المتداخل مع نهاية ServicesHighlight، وضبط سهم الاستعراض ليبقى كاملًا مع النص الطويل وRTL.
3. Latest: فلتر تصنيف منسدل يستعلم من الخادم ويحافظ على الموقع والحالة، مع إلغاء النتائج القديمة ورسالة خطأ حمراء عند فشل الاستعلام. إعادة استخدام النصوص الموجودة في اللغات الـ11.
4. دمج سطر الموقع والتفاصيل وتقليل padding والفواصل دون قص عنوان أو منع تكبير الخط أو تصغير مساحة اللمس الأساسية للبطاقة. لا تغيير وظائف الاتصال أو البيانات.
5. اختبار متصفح مع بيانات معزولة: ضيف وطلبات تجريبية، فلتر ضمن كامل النتائج، استجابة قديمة متأخرة وخطأ، أحجام 360/390/768/1280، لغتان واتجاهاهما، داكن وتباين عالٍ، مع عدم تداخل زر الاستعراض.
6. حفظ ورفع المصدر على claude/deploy-setup، وتشغيل الفحوص الكاملة عبر testdeploy بعد التحقق من نسخة الرجوع. يشمل نشر AYK-170 وAYK-171 المصرح به الآن.
7. إعداد APK موقّع بنفس هوية التطبيق وإتاحة رابط تنزيل متحقق. إن لم تتغير الشيفرة الأصلية فالتنسيق يصل عبر الموقع؛ لا يدّعي APK إصلاح جودة المكالمات. لا رفع للمتاجر أو تغيير latest.json دون حاجة معتمدة.
