# لقطات Google Play — AYK-166

هذه لقطات فعلية لواجهة «أي خدمة» المتجاوبة في Chromium بحجم جوال 360×640 وكثافة 3، فتكون الصور 1080×1920.
تُعرض الواجهة نفسها داخل غلاف أندرويد TWA. هذه ليست تجربة تثبيت على هاتف حقيقي ولا اختبارًا للمكالمات الأصلية.

| الملف | الشاشة |
|---|---|
| `01-home.png` | الرئيسية ومقدم الخدمة القريب |
| `02-services.png` | فهرس المهن |
| `03-request.png` | نموذج الطلب |
| `04-chat.png` | محادثة فعلية مع رسالة محفوظة بعد إعادة التحميل |

## الخصوصية والعزل

- قاعدة PostgreSQL جديدة ومؤقتة، ومستخدمون تجريبيون فقط؛ لا استيراد لبيانات الإنتاج ولا لملف البيئة.
- شبكة Docker داخلية مستقلة بلا منافذ منشورة، ولا وصول لخدمات الرسائل أو الدفع أو المكالمات الخارجية.
- المتصفح يمنع الطلبات إلى أي مصدر خارج نسخة الاختبار؛ الردود من API الحقيقي في النسخة المعزولة، بلا محاكاة لبيانات الواجهة.
- حجب معتم للإعلانات والصور الشخصية والأسماء ومعرفات التواصل. لا تُحفظ رموز الجلسة في الصور أو التقرير.
- الحاويات والشبكة والصورة المؤقتة تُزال عند انتهاء التنفيذ، وتبقى ملفات الصور والتقرير فقط.
- فحوص الأداة ترفض قاعدة خارج نمط حاوياتها، أو متغيرات اتصال تتجاوزها، قبل استيراد كود التثبيت.

## إعادة الإنتاج

من نسخة Git على Linux فيه Docker:

```sh
bash deploy/run-tests.sh
bash deploy/store-screenshots.sh /tmp/ayk-store-shots
```

الأمر الأول يثبت الاعتماديات ويبني الواجهة ويختبرها في حاويات مؤقتة. الثاني يشغّل API والمتصفح وقاعدة مستقلة ويُنتج الصور.
لا يحتاج أي منهما مفاتيح الإنتاج. لا تستخدم `testdeploy` لإنشاء الصور لأنه ينشر الموقع أيضًا.
`verification.json` يسجل نتائج التصوير وبصمات الصور وملفات الأداة؛ `sourceCommit` هو أساس كود التطبيق عند الاختبار، وبصمات الأداة توثّق نسختها المختبرة قبل حفظ التقرير.

لم يُرفع شيء إلى Play Console ولم يُنشر موقع أو تطبيق ضمن هذه المهمة. يراجع المالك الصور قبل رفعها، وتبقى تجربة جوالين ومتابعة المتجرين كما في دليل التسليم.
متطلبات الصور الرسمية: [مساعدة Google Play](https://support.google.com/googleplay/android-developer/answer/9866151).
