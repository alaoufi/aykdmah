# AYK-171 — إطار المحادثات على الجوال

## المشكلة والإصلاح

المحادثات مسار مستقل خارج MainLayout، لذلك لم تكن BottomNav موجودة فيه. ارتفاع chat-page كان 100vh ناقص header-h رغم عدم وجود هيدر الموقع، ولا يعوض تكبير الصفحة. أثبت المتصفح حركة الهيدر خارج العرض عند حجم الخط xl وغياب التنقل السفلي في حالات الجوال.

إطار مستقل بحجم visualViewport مقسومًا على تكبير الصفحة، مع الاستجابة لتغير مساحة العرض وحجم الخط. التمرير داخل القائمة أو الرسائل فقط، والهيدر لا ينكمش. تظهر BottomNav الحالية في قائمة المحادثات؛ داخل المحادثة تبقى مساحة الكتابة دون تداخل مع قائمة التنقل. تُزال قيود التمرير عند مغادرة المسار. عنوان القائمة يستعمل chat.title الموجود بكل اللغات، وسهم الرئيسية يستعمل nav.home كاسم وصول؛ لا مفاتيح ترجمة جديدة ولا تغيير في وظائف الإرسال أو البيانات.

## التحقق

- Chromium قبل الإصلاح: 6 حالات فاشلة من 29 (4 غياب تنقل سفلي، 2 حركة هيدر مع تكبير الخط).
- بعد الإصلاح المبدئي: 29/29 ناجحة على 360×640 و390×844 و1280×800، العربية والإنجليزية، الخط العادي والكبير.
- صورتان مرفقتان من Chromium وWebKit ببيانات اختبار وأسماء طويلة وتواريخ وأكواد ورسائل غير مقروءة، وليست بيانات مستخدمين.
- الفحص النهائي: Chromium 47/47 وWebKit 47/47، بما فيها عرض اللوحي 768×1024، القائمة وحقل الكتابة عند تقليص العرض والقائمة المنسدلة وإرسال رسالة وحفظها بعد إعادة التحميل واستعادة التمرير عند مغادرة المسار. تقريران JSON مرفقان. حارس BASE يحصر التشغيل في مضيف الاختبار المؤقت وحسابه المزروع.
- لا يُعد تصغير viewport اختبار لوحة مفاتيح فعلية. لا جهاز أندرويد أو آيفون مادي متصل، ولا نشر للموقع أو المتاجر ضمن هذه الدفعة.
الفحوص الكاملة: خادم 28/28، واجهة 121/121، تكامل 226/226؛ اللغات الـ11/2255 مفتاحًا، بناء 50.58 ثانية، runtime audit خادم وواجهة بلا ثغرات معلنة، وفحوص نشر ناجحة. التقرير suite.txt. WebKit توقف أولًا في بيئة HTTP بسبب ترقية طلبات الموارد؛ أزيل توجيه upgrade-insecure-requests من وثائق HTTP المؤقتة داخل اعتراض المتصفح فقط، ثم نجحت 47/47. CSP التطبيق والإنتاج لم يتغيرا. التقرير النهائي لا يعتبر توقف الاختبار مع صفر حالات نجاحًا.
