# إدارة Google Play Console وApp Store Connect

## ما الذي سيقدمه وكيل التطوير
- اختيار مشروع أولاً، ثم اختيار المنصة: Web أو Android APK أو Google Play (AAB غالبًا) أو iOS/App Store.
- تجهيز بيانات الإصدار، وصف التحديثات، الصور واللقطات، الاختبارات، والتقرير.
- قراءة حالة التطبيق وإصداراته والمراجعات **بعد** تركيب وصول رسمي محدود الصلاحيات.
- بناء الحزمة وتوقيعها واختبارها بأدوات المشروع وبعد التحقق من بيئة التشغيل.
- طلب موافقة صريحة منفصلة على رفع الحزمة، تقديمها للمراجعة، والإطلاق للجمهور.
- تسجيل رقم الإصدار ومعرف الحزمة ونتيجة كل استدعاء، مع منع نشر نسخة أقدم.

## Google Play
- API: Google Play Android Publisher API (Edits)، Service Account بتفويض التطبيق وصلاحيات محدودة.
- المخرجات: APK للتثبيت المباشر عندما يلزم، وAAB للمتجر.
- التحقق من Package Name وVersion Code وتوقيع Android وتاريخ الإصدار ومسار الاختبار/الإنتاج.
- يمكن عمل draft release، لكن حتى مسودة التعديل التي تُرسل للحساب فعل خارجي يتطلب موافقة أولًا.
- لا يُفعّل الرفع أو تعديل بيانات الحساب تلقائيًا بمجرد أن يكتب المستخدم «حدّث التطبيق».

## Apple
- App Store Connect API Key، أدوار وصلاحيات معتمدة؛ لا تحفظ أي مفتاح هنا.
- استخدام Xcode أو Transporter أو واجهات رفع مدعومة رسميًا وفق بيئة البناء الحالية؛ قد تتطلب macOS.
- لا تخمّن Bundle ID أو Team ID أو App Store App ID، ولا تدّعي جاهزية الرفع دون أدوات التوقيع.
- جهّز بيانات المتجر ونسخة TestFlight عند الطلب، ثم استأذن قبل الإرسال والمراجعة والإطلاق.

## حالة هذا المستودع
- `store-registry.json` سجل إعدادات غير حساس ومبدئي، وليس توثيقًا بأن الحسابات متصلة.
- `projects.json` يحدد لكل مشروع مخرجاته وسياسات الموافقة.
- لا توجد اليوم مفاتيح Store متصلة بهذه الواجهة ولا تم رفع أو تعديل أي تطبيق عبرها.
- قبل تمكين الربط: صلاحيات الحسابات، البيئة المنعزلة، نسخ احتياطية، مراجعة أمان، وتتبّع تدقيق حقيقي.

- Apple: https://developer.apple.com/documentation/appstoreconnectapi
