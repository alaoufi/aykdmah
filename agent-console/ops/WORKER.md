# عامل المهام الخاص

يفصل العامل طابور SQLite عن حساب ChatGPT وعن ملفات المشاريع. يملك الوسيط الموثوق وحده صلاحية Docker. تُشغَّل أدوات النموذج بحساب رقمي محدود داخل حاوية خاصة بالمهمة لها واجهة الشبكة المحلية فقط. يحفظ الوسيط نسخة مستقلة من المشروع في نظام ملفات خاص سعته 1 GiB لكل المهام مجتمعة. يستطيع عميل Codex الرسمي الاتصال بمزوّده، ويتواصل مع أدوات المهمة من خلال مقبس Unix مؤقت. لا يحصل العامل أو حاوية الأدوات على كلمة مرور الواجهة أو بيانات المتاجر أو اعتماد GitHub.

## تجهيز Linux

يتطلب التشغيل Docker وsystemd وPython 3 وGit وext4. نفّذ الخطوات من مجلد agent-console في إصدار Git تمت مراجعته. حافظ على نسخة احتياطية خاصة قبل ترقية قائمة. لا تخلط بين مجلد بيانات الواجهة ومجلد العامل.

1. اختر مسارًا خاصًا كما في الوحدات المرفقة. شغّل أوامر التجهيز كمسؤول. أنشئ مجلد البناء مستقلاً. خزّن هوية كل إصدار منشور ونسخة الملفات السابقة لدى المالك.

    ```sh
    base=/opt/private-agent-console/worker
    install -d -m 0700 "$base" "$base/build" "$base/seeds"
    install -d -m 0700 -o 31072 -g 31072 "$base/auth"
    install -m 0644 ops/bridge.py ops/verify-isolation.py ops/prepare-seed.py ops/screen-seed.py ops/relay.cjs ops/quota.cjs "$base/"
    install -m 0700 ops/subscription ops/install-worker-disk "$base/"
    install -m 0644 ops/private-agent-bridge.socket ops/private-agent-bridge@.service "$base/"
    install -m 0644 ops/Dockerfile.worker "$base/build/Dockerfile"
    docker build -t private-agent-cli:0.147.0 "$base/build"
    sh "$base/install-worker-disk"
    ```

2. تحقّق من المستودع والفرع لكل مشروع. جهّز مرآة bare مستقلة ومتحققًا منها في seeds/aykdmah.git أو seeds/trbhh.git. استخدم مستودع GitHub المقصود فقط وأزل اعتمادات النقل من المرآة. احتفظ بمعلومات الفرع الأصلي وSHA خارجيًا. شغّل تحضير النسخة لكل مشروع. يكتب الملف .source أصل المشروع وSHA النسخة المراجعة. ينشئ التحضير سجلًا جديدًا بلا تاريخ، ويستبعد الملفات الثنائية والروابط الرمزية والأرشيف والمفاتيح والملفات التي تطابق مؤشرات أسرار محددة. راجع الملفات المسموح بها قبل منح الوكيل وصولًا. قد تحتاج اختبارات البناء إلى أصول إضافية من بيئة مراجعة مستقلة.

    ```sh
    python3 "$base/prepare-seed.py" aykdmah
    python3 "$base/prepare-seed.py" trbhh
    sh ops/start-workers
    ```

3. من جلسة SSH خاصة، نفّذ الأمر التالي. يفتح المستخدم صفحة OpenAI ويُدخل رمز الجهاز في متصفحه. لا تُشارك الرمز أو ملف الاعتماد. بعد الدخول يشغّل الأمر تلقائيًا اختبارًا معزولًا باستخدام الاشتراك. يتحقق الاختبار من قراءة علامة عشوائية، وفصل الملفات والشبكة، وتعديل واختبار وتسجيل إصلاح صغير. يُلغى تشغيل مهام المشاريع إلى أن تنجح التجربة على بصمة الصورة والوسيط. بعد تغيير الصورة أو البرامج، أعد الفحص بالأمر الثالث.

    ```sh
    "$base/subscription" login
    "$base/subscription" status
    python3 "$base/verify-isolation.py"
    ```

تُستأنف المهمة المتوقفة قبل التنفيذ من الواجهة بعد نجاح الدخول والاختبار. يتطلب استئناف أي مهمة انقطع تنفيذها مراجعة نسخة المهمة والحاويات والتحقق من توقف العمليات. تحفظ سجلات checkpoints أصل المصدر والنسخة التي بدأ منها التنفيذ. تُراجَع التغييرات قبل تصديرها أو حفظها في فرع تطوير. عند تحديث النسخ المصدرية أوقف العاملين بعد انتهاء المهام، وأرشف المرايا وملفات .source السابقة، ثم أنشئ النسخ التالية وراجعها وأعد تشغيل العاملين. تحقّق من مصدر كل رقعة قبل تطبيقها على الفرع الأصلي لأن نسخة الوكيل لا تحتوي كل الملفات.

يتوقف Claude عند تسليم يدوي للمالك. لا تُشغله لوحة المهام تلقائيًا. استخدم Claude Code الأصلي بتسجيل الدخول الخاص بالمالك عند توفر الحصة والموافقة. راجع [تسجيل الدخول إلى Codex](https://learn.chatgpt.com/docs/auth) و[استخدام اعتمادات Claude Code](https://code.claude.com/docs/en/legal-and-compliance).

تشمل النسخة الاحتياطية الخاصة، مع إيقاف العامل أثناء النسخ، بيانات الطابور، وملف tasks.ext4 بعد إلغاء تركيبه بطريقة آمنة، وحافظة checkpoints وreviewed-seeds وبيانات أصلها. احفظ اعتماد المزود منفصلاً أو أعد تسجيل الدخول بعد الاستعادة. تحقق من فحص القرص والمرايا قبل استئناف مهمة، ثم نفّذ اختبار العزل مجددًا.
