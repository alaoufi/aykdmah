# تشغيل واجهة الوكيل الخاصة

الخدمة معزولة عن المواقع وحاوياتها. تستمع الواجهة على loopback داخل حاوية الشبكة الخاصة. لا تحتوي حاوية الواجهة على Docker socket أو مفاتيح GitHub أو اشتراكات النماذج. يتوقف وصول الهاتف والكمبيوتر على تسجيلهما في شبكة المالك الخاصة والسماح لهما في سياسة الوصول.

## إعداد الخادم مرة واحدة

يتطلب هذا المسار خادم Linux مملوكًا للمشغّل وأدوات Docker وBash وjq وOpenSSL. يُنفّذ المسؤول الأوامر من نسخة معتمدة من مجلد `agent-console`، ويحتفظ بسياسة وصول الشبكة لحساب المالك. تحتاج الأجهزة إلى Tailscale، ويحتاج حساب الشبكة إلى MagicDNS وHTTPS.

```sh
install -d -m 700 /opt/private-agent-console
bash ops/private-web.sh prepare
docker exec agent-console-net tailscale up --hostname=private-agent-console --accept-dns=false
```

يفتح المالك رابط التفويض من الطرفية الموثوقة. كلمة مرور الواجهة في `/opt/private-agent-console/owner-password` متاحة لمسؤول الخادم فقط. لا تنقلها إلى المهمة العامة.

## إصدار الواجهة

استخدم المجلد المستخرج بواسطة `git archive` من الإصدار المطابق للالتزام المرفوع. يُؤخذ احتياطي قبل استبدال خدمة قائمة. يتراجع سكربت التشغيل تلقائيًا إلى حاوية الواجهة السابقة إذا أخفق فحص بدء التشغيل. قبل الرجوع إلى إصدار أقدم تحقق من توافق قاعدة البيانات أو استعد النسخة المطابقة.

```sh
docker build -f Dockerfile.web -t "private-agent-console-web:$REVISION" .
bash ops/private-web.sh stage "$REVISION"
bash ops/private-web.sh serve "$REVISION"
docker exec agent-console-net tailscale serve status
```

يهيّئ `stage` الخدمة داخل الحاوية للفحص الخاص. بعد تسجيل الدخول يستخرج `serve` الاسم الفعلي من حالة الجهاز، ويضبط أصل HTTPS في الواجهة، ثم يُفعّل Serve الخاص في الخلفية. تستخدم الحاويتان سياسة إعادة التشغيل `unless-stopped`. لا تستخدم Funnel. اختبر رابط الواجهة من جهاز مسجّل في شبكة المالك قبل تسليمه.

## النسخ والاستعادة

نفّذ `bash ops/backup-web.sh` من حساب مسؤول الخادم. ينشئ السكربت نسخ SQLite متسقة للطابور والمحادثات والمصادقة، ويتحقق من سلامة كل نسخة ويحفظ أسرار الواجهة في مجلد مقصور على المسؤول. النسخ تحت `/opt/private-agent-console/backups` وتُدار مدة الاحتفاظ حسب سياسة المالك. سجّل نسخًا دورية، وانقل نسخة مشفرة إلى وسيط خارج الخادم حسب سياسة المالك. هذه النسخة تغطي الواجهة والطابور. تحتاج ملفات عمل مهام العامل وهويتا الشبكة والمزود إلى سياسة نسخ أو إعادة تسجيل مستقلة.

للاستعادة، اختر نسخة محددة، افحص `SHA256SUMS`، وأوقف خدمات الوكيل التي تشارك ملفات SQLite. احتفظ بمجلدي البيانات الحاليين كاملين بما فيهما ملفات WAL. استخدم `node backup.cjs restore SNAPSHOT/db NEW_DIRECTORY` من نسخة البرنامج المطابقة داخل بيئة الاستعادة لإلغاء الجلسات وإشعارات الأجهزة القديمة. أنشئ مجلدين جديدين وانقل من ناتج الاستعادة `queue.sqlite` إلى `data/` و`auth.sqlite` إلى `auth/` بملكية `31071:31071` وصلاحيات `0600`. استعد سرّي الواجهة لمسؤول الخادم فقط، ثم أعد إنشاء الحاوية بالإصدار المسجّل لتقرأ السرّين المستعادين. راجع المهام المنقطعة قبل أي استئناف. اختبر تسجيل الدخول والطابور بحساب المالك بعد الاستعادة.
