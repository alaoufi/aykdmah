# الخلفية والتشغيل المتزامن — حالة التنفيذ

## ما أضيف إلى الكود
- تسجيل طلبات المحادثة في ملفات طابور خاصة، ومتابعة حالة كل طلب من الواجهة.
- `worker.cjs` عامل مستقل يمكن تشغيل نسخة منه لكل مشروع، مع تعيين `AGENT_WORKER_PROJECT` إلى `aykdmah` أو `trbhh`.
- قفل مستقل لكل مشروع؛ مشروعان يمكن أن ينفذا بالتوازي من حيث تنظيم الطابور.
- هذا لا يعني أن Claude وCodex يعملان فعليًا حتى يتم ربط جلساتهما رسميًا، وأن يكون `AGENT_WORKER_ENABLED=1` و`AGENT_CLI_ENABLED=1`.
- عند فشل أداة بسبب حد الاستخدام، يحاول المحرك المبدئي الأخرى ضمن وسائل تسجيل الدخول المسموحة. لا يحاول دفع أي رصيد إضافي.

## ما بقي قبل تشغيل خدمة مستقرة
- نقل الطابور إلى قاعدة بيانات متينة: معاملات وقفل lease، وidempotency ومراقبة الأعطال.
- عامل تشغيل دائم مع systemd أو Docker وتفعيل الاستعادة بعد إعادة التشغيل، مع عزل حقيقي لمجلدات وصلاحيات كل مشروع.
- ضبط التزامن على مستوى اشتراك Claude وCodex، لا على مستوى المشروع فقط: لا يجوز أن تحاول عمليتان سحب الحصة نفسها دون مراقبة.
- تكوين إشعارات Web Push أو بريد عند اكتمال المهمة. لا توجد إشعارات خارج التطبيق فعليًا حتى الآن.
- حماية تسجيل الدخول وCSRF، وأمان CLI ومخرجاته وسجل الأخطاء قبل النشر.
- اختبارات تشغيل وانقطاع الشبكة واستعادة الطابور، مع اختبار متزامن لمشروعين منفصلين.

## الرسالة عند انتهاء مهمة
تعرض لوحة الوكيل حالة المهمة ووقتها وملخصًا محفوظًا؛ ويجب ألا يصل إلى شاشة القفل محتوى حساس. التنبيهات المستقبلية تتطلب اشتراك المستخدم بها، وربط خدمة إشعار موثوقة.
