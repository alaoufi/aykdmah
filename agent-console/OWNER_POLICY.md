# سياسات الوكيل المركزي — جميع المشاريع

## سياسة المالك
- أولوية اللغة العربية وواجهات RTL عند الاقتضاء.
- أدوات AI المدفوعة المسموح بها فقط: اشتراك Claude Code واشتراك Codex/ChatGPT. **لا تفعّل واجهات API بفوترة مستقلة**.
- عند بلوغ حد أحدهما، تحقق من إمكان تشغيل الثاني بواسطة وسيلة الدخول الرسمية؛ انقل حالة المهمة والأوامر والتغييرات التي حُفظت دون إعادة العمل. لا تحاول تجاوز الحصص أو استخدام حسابات التفاف. إذا لم يتوفر الاثنان، سجّل المهمة متوقفة مع السبب.
- صنّف الطلب بحسب الكفاءة والجودة والتوافر، واسمح بالتشغيل المتوازي للمهام المستقلة فقط.
- لا تنفذ عملية دفع أو نشر أو تغيير DNS أو حذف بيانات إنتاج أو رفع متجر دون موافقة صريحة لكل عملية.
- **كل مشروع ملف مستقل**: مستودع GitHub، فرع تطوير حقيقي، متطلبات وتسليمات، قاعدة بيانات، بيئة اختبار، سجل تعديلات ونشر.
- لا تنشئ ملفات APK أو iOS لمشروع Web-only؛ ولا تفرض تطبيق ويب على مشروع Android-only.
- المشروع الجديد يضاف بموافقة المالك بعد التحقق من المستودع والصلاحيات ونوع المخرجات.
- لا تُعامل الادعاءات الواردة في مستند التسليم على أنها إثبات نشر؛ تحقق من الـ commit والسجلات والنتائج.

## خط سير أي مهمة
1. اختيار المشروع قبل الكتابة. تبقى المحادثات محفوظة حسب المشروع.
2. قراءة `projects.json` وتعليمات المشروع والمهام المفتوحة.
3. تحديد نوع المهمة ومخاطرها وأداة التنفيذ المتاحة عبر تكامل رسمي، مع عدم ادعاء امتلاك معلومات الحصة إن لم توفرها الأداة.
4. إنشاء مهمة وربطها بفرع منفصل والاحتفاظ بسجل تشغيل قابل للتدقيق.
5. الاختبارات المحلية المناسبة بحسب المنصة؛ عند فشلها تصحيح ثم إعادة الاختبار.
6. مراجعة أمنية/وظيفية عند التعامل مع الدفع والصلاحيات والمكالمات وقواعد البيانات ومتاجر التطبيقات.
7. تقديم ملخص بالعربية: الملفات والـ commit والاختبارات والمهام المتبقية وحالة النشر.
8. لا يدمج تغييرات الإنتاج ولا ينشرها إلا بعد الموافقة.

## Android
- تصنيف المخرج: `android-apk` للتثبيت المباشر، و`android-aab` لإصدار Google Play.
- راجع package ID، build/versionCode، التوقيع، صلاحيات Android، سياسة الخصوصية، Data Safety، وآليات التحديث.
- لا ترفع keystore، شهادة توقيع، رموز Play Console، أو ملف `.env` إلى GitHub.
- الإنشاء والاختبار لا يعنيان نشرًا في Google Play. يتطلب النشر صلاحية وصول معتمدة وموافقة مالك الإصدار.

## iOS / App Store
- راجع Bundle ID، رقم الإصدار والبناء، الشهادات والتوقيع، ملفات الخصوصية، الإشعارات، App Store Connect وحالة المراجعة.
- تحتاج عملية البناء والتوقيع موارد Apple وتفويضًا رسميًا. لا تفترض القدرة على رفع التطبيق لمجرد وجود كوده.
- يظل إرسال التطبيق للمراجعة أو إطلاقه قرارًا منفصلًا للمالك؛ لا تتجاوز شروط Apple.

## Web
- افصل التطوير عن نشر الإنتاج، وراجع اختبارات المتصفح والبناء والخدمات والـ HTTPS وإصدار الخادم.
- لا تغير DNS أو قواعد بيانات العملاء دون إذن.

## حدود الإصدار الحالي
تُحفظ المحادثات في قاعدة بيانات خاصة. يتولى عامل مستقل التسليم إلى Codex بعد تسجيل الاشتراك في بيئة التشغيل، وتظل مخرجاته بانتظار التحقق. يتاح تسليم يدوي إلى Claude Code بعد مراجعة المالك للنص. راجع README.md وBACKGROUND_JOBS.md للتشغيل والاستئناف.

## سياسة اعتماد نماذج الذكاء الاصطناعي (قرار المالك)
- **Claude Code وCodex فقط** أدوات تنفيذ أساسية معتمدة.
- Qwen Studio وDeepSeek وKimi وأي نموذج آخر: **غير معتمد للتنفيذ أو المراجعة الإنتاجية** حتى يُثبت جودة نتائجه في اختبارات مستقلة مقارنة بمعايير القبول، ويحصل على موافقة جديدة صريحة من المالك.
- لا تستخدم النماذج غير المعتمدة تلقائيًا عند نفاد حصة Claude أو Codex؛ علّق المهمة حتى يتاح أحدهما.
- لا تُرسل كودًا أو بيانات خاصة إلى أدوات تجريبية دون تصريح مستقل.
- لا API مدفوعة أو اشتراكات AI إضافية.
